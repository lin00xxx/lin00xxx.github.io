1. 排序基础

1.1 定义

把一组记录按某个关键字的递增或递减顺序重新排列，使无序变有序。

1.2 四个评价指标

指标 含义 备注
时间复杂度 比较/移动次数随 n 的增长 分最坏、平均、最好三种情况
空间复杂度 额外占用的内存 O(1) 即原地排序
稳定性 关键字相等的元素，排序后相对顺序不变 见下
适应性 对不同数据（近乎有序、范围小等）的表现 如插入排序对近乎有序数据极快

稳定性为什么重要：多级排序时需要。例如先按姓名排，再按成绩排；若成绩排序稳定，则同分者仍保持姓名顺序。

1.3 分类

1.4 按思想再归一次（帮助记忆）

思想 算法 一句话
交换 冒泡、快速 通过交换逆序对消除无序
选择 选择、堆 每次选出最值放到最终位置
插入 插入、希尔 把新元素插进已有序部分
分治 归并、快速 拆小 → 解决 → 合并
计数/分配 计数、桶、基数 不比较，直接“定位”

2.2 选择排序 (Selection Sort)

思想：把数组分成“已排序区（前）”和“未排序区（后）”。每趟在未排序区中选出最小值，与未排序区的第一个元素交换，已排序区扩大一格。

过程（64 25 12 22 11）：

循环边界

  • 外层 i：0 到 n-2，共 n-1 趟。
  • 内层 j：i+1 到 n-1，用 k 记录最小值下标。
  • 每趟只交换一次：a[i] 与 a[k]。

优化（课件 ☆）：一趟同时选最大和最小，两端同时收缩，趟数减半。

为什么不稳定：[5a, 5b, 2] 第一趟把 2 与 5a 交换 → [2, 5b, 5a]，两个 5 的顺序反了。长距离交换是根源。

时间（三种情况） 空间 稳定性
都是 O(n²)（不管有序与否，比较次数固定） O(1) 不稳定

2.3 插入排序 (Insertion Sort)

思想：像整理扑克牌。左侧是已排好的手牌，每次从右边抓一张新牌，从后向前扫描，找到合适位置插进去。

步骤

  1. 第 0 个元素视为已排序。
  2. 取下一个元素 key，在已排序部分从后往前扫描。
  3. 已排序元素 > key 就后移一位。
  4. 直到遇到 ≤ key 的元素（或越过开头），把 key 放到空位。
  5. 重复直到结束。

过程（5 2 4 6 1 3）：

特点：数据越接近有序越快（最好 O(n)）。这一点是希尔排序和快排“小区间优化”的理论基础。

平均/最坏 最好 空间 稳定性
O(n²)（最坏：完全逆序） O(n)（已有序） O(1) 稳定

2.4 希尔排序 (Shell Sort)

动机：插入排序慢，是因为元素一次只能挪一格；但它在“基本有序”时很快。希尔的做法：先让数据大步流星地基本有序，最后再用一次插入排序收尾。

思想：取增量 gap，把所有距离为 gap 的元素归为一组，各组内部做插入排序（称“预排序”）。逐步缩小 gap，直到 gap = 1，此时就是一次普通插入排序，但数据已基本有序，代价很低。

  • gap 大：元素跳得远，但不够精细；
  • gap 小：精细，但移动慢。
  • 常用序列：gap = n/2, n/4, …, 1；或课件的 gap = gap/3 + 1。最后一轮必须是 1。

复杂度：与增量序列有关，没有完整的理论结论。

  • 最坏 O(n²)；平均约 O(n^1.3) ~ O(n^1.5)（实验统计，非理论证明）；

≈ O(n^1.3) O(n²) O(1) 不稳定

2.5 快速排序 (Quick Sort)

起源：1960 年 C. A. R. Hoare 提出，是对冒泡排序的重大改进（冒泡每次只交换相邻元素，快排一次交换能跨越很远）。

思想：分治

  1. 选一个基准数 key；
  2. 分区 (partition)：把比 key 大的放右边，≤ key 的放左边，key 落在最终位置；
  3. 对左右两个区间递归重复，直到区间只剩 ≤1 个元素。

关键：一趟分区之后，key 已经在最终位置上，不会再动。

分区的双指针做法（课件主版本）

  • begin 从左往右、end 从右往左，基准取 a[left]（下标记 keyi）。
  • 先动 end：找到 <= key 的停下；
  • 再动 begin：找到 > key 的停下；
  • 若 begin < end：交换，继续；
  • 相遇后：swap(a[keyi], a[begin])，key 落位，返回其下标。

为什么必须右边先走？ 相遇位置的值必须 ≤ key 才能与 key 交换。右边先走时，相遇点要么是 end 停下的 ≤key 元素，要么是 begin 追到的、已被换过去的 ≤key 元素。若左边先走，相遇点可能是 >key 的值，换到首位就错了。（基准取左端时的规则；取右端则反过来。）

其他版本：挖坑法

先把 key 取出，留下一个“坑”，右边找小的填坑、左边找大的填坑，轮流进行，最后把 key 填入最后的坑。课件 p33 的图示即此过程。

优化一：三数取中

问题：数组已有序/逆序时，若基准恰好是最小/最大值，每次分区得到“空 + 几乎整个数组”，递归深度退化到 n，整体 O(n²)。

做法：比较 a[left]、a[mid]、a[right]，取中间值作基准，并把它换到 left，其余代码不变。

随机选基准也能达到同样目的。

优化二：小区间改插入排序

区间很小时，递归调用 + 栈帧开销大于收益，而插入排序对小数组很快。

性能

情况 时间 原因
最好 O(n log n) 每次均分，递归树高 log n，每层总计 n 次比较
平均 O(n log n) 随机数据
最坏 O(n²) 基准总是极值，如有序数组 + 取首元素
  • 空间：O(log n)（递归栈，最坏 O(n)，优化后基本不出现）
  • 稳定性：不稳定（分区时的远距离交换会打乱相等元素）。需要稳定请用归并。

2.6 归并排序 (Merge Sort)

思想：分治——“先拆到不能再拆，再两两有序合并”。

  1. 分解：mid = (left + right) / 2，把区间一分为二；
  2. 解决：递归排序左半 [left, mid]、右半 [mid+1, right]；
  3. 合并：把两个有序的半区间合成一个有序区间（核心）。

递归出口：区间只有一个元素（本身有序）。

图示（38 27 43 3 9 82 10）：

合并步骤（升序）

  1. 两个指针 i、j 分别指向左、右半区起点；
  2. 比较 a[i] 与 a[j]，较小者先放入临时数组 tmp，对应指针后移；
  3. 一直到某一半取完；
  4. 把另一半剩余元素直接接到 tmp 末尾；
  5. 把 tmp 对应区段拷回原数组。

实现要点：合并需要与原数组等大的临时数组。主函数一次性申请，子函数全程复用，避免反复申请/释放的开销。

复杂度直觉：递归树共 log n 层，每层合并总共处理 n 个元素 → O(n log n)。输入是什么样都不变，所以最好/最坏/平均全是 O(n log n)。

时间 空间 稳定性
O(n log n)（三种情况相同） O(n)（临时数组） 稳定

应用：数据量大到装不进内存（外部排序）时，可以分文件各自排好序，再做合并。

2.7 计数排序 (Counting Sort)

非比较排序。不比较元素大小，而是统计每个值出现几次，再据此还原有序序列。

适用条件：数据是范围确定且不大的整数（成绩、年龄等）。

步骤

  1. 确定数据范围（求 min、max，范围 k = max - min + 1）；
  2. 初始化长度为 k 的计数数组，全 0；
  3. 遍历原数组，cnt[a[i] - min]++；
  4. 按值从小到大输出：值 v 输出 cnt[v] 次；
  5. 释放计数数组。

过程（2 5 3 0 2 3 0 3，min=0，max=5）：

稳定版（用于对象排序，是基数排序的基础）：对 cnt 做前缀和，cnt[v] 变成“值 ≤ v 的元素个数”，即 v 的最后一个位置+1；然后从后往前扫描原数组放位置。

时间 空间 稳定性
O(n + k) O(k) 稳定（用前缀和版本）

注意：k 远大于 n 时（如 n=10，值域 10⁹）反而更慢、更耗内存，别用。

2.8 补充：堆排序 / 桶排序 / 基数排序

课件对比表中出现，但未展开。这里给出核心逻辑。

堆排序：用大顶堆（父 ≥ 子）。

  1. 建堆：从最后一个非叶子结点 n/2-1 往前依次“下沉”；
  2. 重复：堆顶（最大值）与堆尾交换，堆大小减 1，对堆顶下沉。

时间 O(n log n)（三种情况相同），空间 O(1)，不稳定。

桶排序：把值域分成若干区间（桶），元素按值分到各桶，桶内各自排序，再按桶顺序拼接。数据均匀分布时接近 O(n)；全挤进一个桶则退化为桶内排序的复杂度（表中最坏 O(n²)）。

基数排序（LSD）：按位数从低位到高位，依次对每一位做稳定的计数排序。正因为每轮稳定，高位排序不会破坏低位已排好的顺序。

时间 O(d·(n+k))，d 为位数，k 为基数（这里 10）。

两个常见坑

5. 排序例题

5.1 快乐的蠕虫 The Happy Worm（1352）

题意：m×n 网格，k 块石头。蠕虫睡觉时横着或竖着，尽可能伸展，不能越界、不能压石头，长度至少 2。问有多少个不同的睡觉位置。数据范围 m, n, k ≤ 200000。

理解题意（最关键）

  • “尽可能伸展” → 一段连续空格只对应一个位置，不论蠕虫头在哪（第 1 列有 4 个连续空格，只算 1 个，不算 3 个）。
  • “长度 ≥ 2” → 只计算长度 ≥ 2 的极大连续空段。
  • 所以问题 = 统计所有行、列中长度 ≥ 2 的极大空段数量。

为什么不能建二维数组：m×n 最大 4×10¹⁰，内存放不下，二重循环扫描也必然超时。

解法：只存石头，排序后扫描相邻石头

  1. 在网格四周“添加”一圈虚拟石头（第 0 行、第 m+1 行、第 0 列、第 n+1 列，共 2(m+n) 块，角落不用），这样每一段空格两端都有石头，不用特判边界；
  2. 按行排序：先按 x（行）升序，x 相同再按 y（列）升序。排序后，同一行的石头依次相邻。若相邻两块 x 相同、且 y 差 > 2，则中间有 ≥ 2 个空格 → 一个横向位置；
  3. 按列排序：先按 y 升序，y 相同再按 x 升序；同理，相邻两块 y 相同、x 差 > 2 → 一个纵向位置。

为什么是 “差 > 2”：两块石头坐标差为 d，中间空格数是 d−1；要求空格数 ≥ 2，即 d ≥ 3，d > 2。

样例核对（5×5，6 块石头）：横向 5 行各 1 段 = 5；纵向第 1、2、4、5 列各 1 段 = 4（第 3 列没有）；合计 9 ✓。若去掉 (4,2) 的石头，第 4 行 (4,3) 左边也成一段，变 10。

复杂度：O((k+m+n) log(k+m+n))，只存石头，内存 O(k+m+n)。

从这题带走的思想：数据太大不能存全图时，只存“关键点”，用排序把相关的点聚到一起，再线性扫描相邻项。

5.2 单词重组 Word Amalgamation（1353）

题意：给定一部字典（1~100 个单词，每个 ≤6 个小写字母，以 XXXXXX 结束），再给若干个被打乱字母的单词（以 XXXXXX 结束）。对每个乱序词，按字典序输出字典中所有能由它重排字母得到的单词；没有则输出 NOT A VALID WORD；每组结果后输出一行 ******。

核心逻辑：两次排序

  1. 字母排序 → 判断“能否重排成” 两个单词能互相重排，当且仅当它们字母排序后完全相同。 例：trap、tarp、part 排序后都是 aprt。 所以对字典里每个单词预先算好“签名”（字母排序后的串），对每个乱序词也算签名，比较一次字符串即可，不必逐一尝试全排列。
  2. 字典排序 → 控制输出顺序 题目要求按字母序输出，而不是按字典中出现的顺序。所以先把字典单词按字典序排序，查找时从前往后扫，命中的自然就是有序的。

样例推演：字典排序后 course earn first … part pepper refund score tarp trap work；乱序词 aptr 签名 aprt，命中 part, tarp, trap（按字典序）。

注：课件 p68 的“样例输入/输出”是误贴的蠕虫题数据，真正的样例在 p69。

从这题带走的思想：判断“字母构成相同”用排序后比较（规范化）；“输出有序”用预先排序。一道题里排序可以有两个不同的用途。

6. 易错点与复习清单

6.1 易错点

点 说明
冒泡内层边界 i < n-1-j，否则越界或多比较
选择排序交换次数 每趟只交换一次；双向优化时注意 mx == l 的特例
插入排序 用后移而不是反复交换；条件写 a[j] > key（严格）才稳定
希尔最后一轮 gap 必须以 1 结束
快排指针顺序 基准取左端 → 右指针先走
快排的 <= / > 不写等号可能死循环、递归不收敛
快排退化 有序数据 + 取首元素 = O(n²)，用三数取中/随机
归并合并 比较用 <= 才稳定；别忘了处理剩余元素与拷回
计数排序 值域过大不适用；有负数要减去最小值做偏移
qsort 比较函数 相减可能溢出；double 不能相减后返回 int
sort 比较函数 不要用 <=/>=，否则可能 RE
sort 区间 [first, last)，last 是末尾的下一个位置
